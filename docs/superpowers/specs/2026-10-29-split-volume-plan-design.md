# 训练计划：分化替代频次 + 每轮容量校准

## 背景

计划不再绑定日历后，「频次（每周练几次）」不再是计划参数。真正决定计划结构的是**分化**：一次循环里排几个训练日、如何分布肌群。本次同时按肌群每轮直接组重新校准模板，解决现有计划的容量不平衡。

## 分化

| 分化 | 每轮训练日 | 循环 |
| --- | --- | --- |
| 全身 | 2 | 全身 A/B |
| 推拉腿 | 3 | 推 / 拉 / 腿（三日专项模板） |
| 上下肢 | 4 | 上肢 A / 下肢 A / 上肢 B / 下肢 B |
| 五分化 | 5 | 上肢 / 下肢 / 推 / 拉 / 腿 |
| 推拉腿 ×2 | 6 | 推 A / 拉 A / 腿 A / 推 B / 拉 B / 腿 B |

`PlanConfig.days` 改为 `split: SplitId`；旧存档的 `days` 映射为对应分化。周期仍为 8 轮、分期 2/3/2/1 轮，一轮 = 一次完整分化。

## 容量口径

- 直接组：动作中该肌群主动肌计 1 组、协同肌计 0.5 组；同一动作对同一肌群只取最高计入一次，避免重复计数。
- 审计肌群 10 组：胸、背阔、上背/后束、股四头、臀/腘绳、肩中、二头、三头、小腿、核心。
- 每轮参考区间：大肌群 9–26、臀/腘绳 10–26、上背/后束 10–30、小肌群 7–18、核心 6–20。
- 三种目标共用组数区间；目标差异体现在次数、负荷与休息，代谢收尾不计入力量容量。
- 区间再按分期（适应 0.8 / 容量 1 / 强度 0.85 / 减载 0.65）、水平（入门 0.85 / 进阶 1 / 高阶 1）与分化（全身 2 练/轮 0.8，其他 1）折算。
- 肩前不单列：推类动作会间接覆盖，避免与胸重复计数。

## 模板与处方

- 分化专属组数加成：全身与推拉腿主项 +1；上下肢、五分化、推拉腿×2 不加成。孤立动作不再叠组；减载期不应用分化加成。
- 入门在二级、孤立、核心上 −1 组，最低 2 组；高阶用更难的动作和更高负荷，不抬高目标区间。
- 容量期单次组数控制在：全身 27–36、PPL 19–29、上下肢 12–26、五分化 12–23、PPL2 12–22；减载期总组数相对容量期下降约 40%（实测 38–45%）。
- 全身 A/B 补齐胸、三头、小腿，并增加肩中；推拉腿三日模板单独设计，补齐胸、背、手臂、小腿与股四头；上下肢补齐二头/三头与小腿；五分化补齐三头、小腿；六分化移除 B 推日的肩推以控制肩前容量，并精简上背槽位。
- 平行推按“器械 → 哑铃 → 杠铃”排列；上斜推按“上斜俯卧撑 → 哑铃上斜 → 杠铃上斜”排列；同一天不重复抽到同一个动作。
- 小腿双槽位区分腓肠肌（站姿/驴式）与比目鱼肌（坐姿）；PPL 的水平拉与二头槽位分别使用独立候选池。
- 页面移除「频次」，改为分化卡；阶段卡显示「第 a–b 练 · N 轮」。
- 侧栏新增「本轮计划容量」审计卡：按当前轮的处方累计直接组，与分期/水平/分化折算后的目标区间对比，标出不足、达标、偏高。

## 验证

- `pnpm typecheck`、`pnpm build` 通过。
- 遍历 3 种水平 × 3 种目标 × 5 种分化 × 4 个分期，十个肌群审计项全部落在目标区间。
- 遍历 3 种水平 × 5 种分化，同一训练日无重复 exerciseId；容量期单次组数不超过 36；减载期总组数相对容量期下降 38–45%。
- 浏览器验证：切换分化后训练序列与总次数正确、容量审计随分化/分期/水平变化、旧 `days` 配置与日期记录迁移成功。
